# Product and Design References

## Purpose

Use references to learn product structure, page patterns, trust signals, and student accommodation workflows. Do not copy brand identity, exact layouts, text, protected assets, or proprietary UI.

## Primary Reference: Amber Student

Reference:

```text
Amber Student
```

Source:

```text
https://amberstudent.com/
```

Why it matters:

```text
Amber is a mature student accommodation marketplace. It shows how to structure global/city/university search, listing pages, hostel detail pages, room types, trust badges, offers, reviews, FAQs, and long-form SEO content.
```

What to learn:

```text
1. Home page search by city, university, or property.
2. Strong trust signals near the hero: verified properties, 24/7 assistance, lowest price guarantee.
3. Large marketplace stats: beds, universities, cities.
4. Country/city/university browsing hierarchy.
5. Listing page with filters for university, locality, budget, move-in month, stay duration, room type, amenities, and bills included.
6. Listing cards with image, name, address, distance, commute information, offers, room options, amenities, rating, and starting price.
7. Detail page with image gallery, map view, rating, address, price, distance to campus/city, amenity chips, offers, property description, features, commute, room types, house rules, payment/fees, resident mix, and FAQs.
8. SEO content below listings: area guide, accommodation guide, cost of living, transport, lifestyle, tourist attractions, universities.
```

What not to copy:

```text
1. Amber branding, color system, logo, copywriting, exact layout, or proprietary assets.
2. Global student housing claims that do not apply to Ghana.
3. Heavy international booking/legal flows before Ghana MVP needs them.
```

How to adapt for UCC MVP:

```text
1. Replace country/city hierarchy with University -> Campus/Area -> Hostel.
2. Start with UCC and Cape Coast areas, then support KNUST, UG, UPSA, UEW, UDS, TTU, and others later.
3. Replace weekly UK pricing with Ghana semester/year pricing.
4. Replace visa/no-visa policies with Ghana-relevant trust signals: verified owner, inspected hostel, student ID/accountability, direct owner contact, secure payment later, refund/deposit rules when supported.
5. Add Ghana-specific filters: area, distance to campus gate, shuttle/taxi access, room sharing count, water reliability, electricity/prepaid, security, kitchen, washroom type, gender preference if applicable, semester availability, academic year availability.
```

## Marketplace Search Reference: Expedia

Reference:

```text
Expedia Europe
```

Source:

```text
https://euro.expedia.net/
https://euro.expedia.net/Hotels
```

Why it matters:

```text
Expedia is a mature search-first marketplace. It shows how to make a complex discovery flow feel simple through a strong search module, travel category tabs, travellers/rooms selectors, member sign-in value, destination cards, support/trips links, and a clear property-owner listing path.
```

What to learn:

```text
1. Search-first home page with product/category tabs.
2. Clear search fields: destination, dates, travellers/rooms, and search CTA.
3. Traveller/room selector with steppers and a done action.
4. Member sign-in banner that explains why signing in has value.
5. Destination card carousel for browsing.
6. "List your property" owner/manager CTA in navigation.
7. Support, trips, communication center, currency, and account links as trust/utility navigation.
8. Footer link structure for SEO, company, help, policies, and travel guides.
9. Post-search results page becomes more serious and task-focused after the user searches.
10. Desktop listing page uses a dense but readable structure: search bar on top, left filter rail, result list, sort, map preview, and structured cards.
11. Mobile adjusts the same workflow into focused stacked controls instead of stretching desktop columns.
12. Account/onboarding flow uses small centered forms, progressive steps, disabled states, loading states, email confirmation, password creation, and membership welcome states.
```

What not to copy:

```text
1. Expedia branding, copywriting, iconography, colors, exact layout, or proprietary assets.
2. Flight/car/package/cruise product categories that do not belong to Hostel Premium.
3. Hotel-room booking/payment assumptions for the MVP.
4. Member-discount language unless Hostel Premium actually offers a student/owner benefit.
```

How to adapt for Hostel Premium:

```text
1. Expedia's "Stays / Flights / Cars / Packages" tabs become Hostel Premium discovery modes:
   - Hostels
   - Areas
   - Map
   - Verified
   - For Managers
2. "Going to" becomes University / Area / Hostel search.
3. "Check-in / Check-out" becomes Move-in period / Academic year / Semester availability.
4. "Travellers / Rooms" becomes Room type / Occupants / Gender preference if needed.
5. Member sign-in banner becomes:
   "Sign in to view full hostel details, save options, and send safe enquiries."
6. Destination cards become UCC area cards:
   Apewosika, Amamoma, Kwaprow, Ayensu, Science, Old Site/New Site.
7. "List your property" becomes:
   "List your hostel" or "For Hostel Managers".
8. Support/trips links become:
   Support, My Requests, Saved Hostels, Messages.
9. SEO/footer links become:
   UCC hostel guide, areas near UCC, hostel safety, verification meaning, manager listing guide.
10. Expedia's post-search hotel listing becomes Hostel Premium's serious comparison page:
   - top search summary: UCC/area, move-in period, room type/occupants
   - left rail: map preview, search by hostel name, filters
   - center/right: results count, sort, benefit/trust banner, hostel cards
   - card: image/gallery, save action, hostel name, area, room type, amenities, trust label, price/range, availability, CTA
11. Expedia's mobile adaptation becomes a strict responsive rule:
   - no stretched mobile view on desktop
   - no squeezed desktop filter rail on mobile
   - mobile uses sticky search summary, filter/sort/map buttons, bottom sheets, and single-column cards
```

### Home

Use:

```text
Search by university, area, hostel name.
Popular chips: UCC, KNUST, UG, UPSA, UEW.
Trust row: verified hostels, UCC-first coverage, student support, transparent prices.
```

Avoid:

```text
Generic real-estate hero that does not feel student-specific.
```

### Listing / Search

Use:

```text
Desktop: filter sidebar + results + optional map/area context.
Mobile: search header + filter sheet + single-column hostel cards.
Filters: university, area, budget, room type, occupancy, amenities, distance, availability, verification.
```

Avoid:

```text
Stretched mobile layout on desktop.
```

### Hostel Detail

Use:

```text
Image gallery, address/area, distance to campus, room types, semester prices, amenities, rules, availability, owner/verification status, request CTA, map/location context, FAQs.
```

Avoid:

```text
Long unstructured text without decision-making information.
```

### Booking / Request

Use:

```text
Collect student name, phone/WhatsApp, school, level if needed, preferred room type, move-in period, budget, notes, and consent.
```

Avoid:

```text
Taking payment before owner verification, cancellation rules, and support workflow are fully planned.
```

## Open Questions From References

```text
1. Should MVP support only booking requests, or real room reservation?
2. Should payments be excluded from MVP, or should we plan Paystack/Hubtel for a later phase?
3. Will UCC hostel data be manually entered by admin first, or submitted by hostel owners?
4. Should hostel verification be visible to students from day one?
5. Should the first version include maps, or only area/distance text until data quality improves?
```
