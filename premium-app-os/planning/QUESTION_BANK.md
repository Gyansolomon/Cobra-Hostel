# Question Bank

Use these questions during project discovery. Ask only what matters for the current project.

## Product

1. What are you trying to build in one sentence?
2. What should this product help users do?
3. What problem is painful enough that users will care?
4. What does success look like for version 1?
5. What should not be included in version 1?
6. What is the long-term vision?

## Users

1. Who is the primary user?
2. Who is the buyer or decision maker?
3. Are there admins, owners, support users, or viewers?
4. What does each role need permission to do?
5. What does a new user need to understand in the first minute?

## Business

1. Is this for learning, internal use, a startup, client work, or public launch?
2. How will the product make money, if at all?
3. Does the app need subscriptions, payments, bookings, commissions, ads, or leads?
4. What is the budget for APIs, hosting, components, tools, and design assets?
5. What deadline matters?

## Platform

1. Should this start as mobile, web, admin dashboard, or both?
2. Does it need offline support?
3. Does it need push notifications?
4. Does it need realtime updates?
5. Does it need location, maps, camera, uploads, files, or payments?

## Design

1. What should the app feel like?
2. Are there brand colors or a logo?
3. What apps or websites should inspire the design?
4. Which screens need the most polish?
5. Should visuals use photos, illustrations, 3D, icons, maps, or charts?
6. Are paid design assets allowed?

## Data and Backend

1. What records are permanent?
2. What information is private?
3. What roles and permissions are needed?
4. What actions need audit logs?
5. What data can be cached?
6. What data must never be exposed to the client?

## Tools and Agents

1. Is GSD Core installed or should we ask to install it?
2. Should Multica manage multiple agents, or is one Codex session enough?
3. Which MCP connections would help: Figma, GitHub, Gmail, Browser, Supabase, Firebase, Stripe, Linear, Notion?
4. Does the user have accounts and credentials ready?
5. Should we avoid paid tools and subscriptions?

## Scope Control

Ask these when the project feels too large:

1. What is the smallest useful version?
2. What can be mocked first?
3. What can be manual behind the scenes?
4. What can wait until after launch?
5. Which feature proves the product is worth continuing?
